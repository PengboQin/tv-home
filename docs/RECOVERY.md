# 退出、升级与恢复

## 遇到异常先退出

1. 按遥控器返回；再试原厂 Home/输入源，回到原桌面或 HDMI。当前 App 没有默认 HOME/开机接管。
2. 如果 App 不响应，获得停止本 App 授权后，仅对确认的目标执行：

```sh
adb -s '已确认的目标' shell am force-stop com.pengboqin.tvhome.preview
```

3. 下次从 App 列表打开。检测到本 App 的 Java 崩溃记录或已保存的渲染器故障状态时，会先暂停 HA 加载。可继续使用 App 列表和设置，查诊断，再明确选择恢复网页。并非所有 ANR/掉电/系统故障都能被捕获。
4. 若整个电视无响应，停止自动化，使用厂商原有的人工恢复/支持路径；不要让 Agent 自动重启、刷机或恢复出厂。

## 升级前保留什么

- 当前可用 APK及SHA256、versionCode、同一个签名证书指纹、源代码commit、配置schema。
- 上一份真正验证过的候选，以及你需要保留的本 App 配置。当前没有用户配置导出/导入功能，WebView会话也不是一个可随意公开复制的文件。
- 自建者的 `.private/` 签名目录：离线加密保管。**不要提交Git、发Issue或发给Agent服务。** 丢失密钥后不能以同签名更新，不能承诺有办法恢复。

官方预览、自建包以及别人fork的包可能用同一个applicationId、不同签名；先核验，不得自动卸载解决签名冲突。可在开发分支修改applicationId做隔离实验，但不能假装这是保数据升级。内部实验包与公共包不同，安装公共包不会迁移内部配置。

## APK降级是高级恢复操作

只有在用户确认目标和恢复范围、旧新APK同签名且配置schema兼容、并且持有旧包时才评估 `adb install -r -d <旧APK>`。Android/厂商固件可能拒绝对非调试包降级；**公共包 debug=false，因此不能承诺这个命令可用**。拒绝时停止，不改系统限制，不卸载后冒充成功回退。

内部调试包做过同签名 `4→3→4` 保数据回退；这不能当成公共非调试包或任意未来数据schema的回退保证。公开版出问题时，第一恢复方式是停止使用本 App、回原厂桌面；优先提供修复后的更高versionCode包。必要的数据删除/重装由用户在理解后果后单独决定，不能写入一键脚本。

**App回退不等于电视固件恢复，也不恢复HA服务器、VPN/网络、HDMI或音频设置。** 本 App本来就不应改这些。出现异常设置变化先记录和调查，不能盲目把旧快照整机覆盖回去。

## 调试结束

App 日常工作不依赖 ADB。按用户选择在原系统设置关闭网络调试、撤销不需要的电脑授权；若用户明确在继续开发，不擅自断开或改变其长期设置。不要通过新增持久属性“记住开启状态”。不需要本 App 时，可通过原系统应用设置移除，但会丢失本 App配置/会话，先告知数据影响。
