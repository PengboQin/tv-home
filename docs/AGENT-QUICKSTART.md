# 给用户与 Agent 的配置流程

这里的命令是供阅读、核对和按阶段执行的示例，**不是一键授权脚本**。安装普通 App 通常可回退，但整机调试、家电操作和数据删除的范围不同。

## 0. 先问什么

一次性确认：电视品牌/型号、Android 版本、系统 WebView、正在看的输入源、遥控器种类（蓝牙/红外/手机）、HA 地址及登录方式、是否有可用的原厂桌面和遥控器、希望只评估还是允许安装/启动测试。

不确定的语音输入要核对；不要据此猜测“可以关机”“可以删除系统桌面”。HA 账号密码由用户在电视原网页输入。网址使用 HTTPS；当前代码也接受 RFC1918 IPv4 的 HTTP，但有明文风险。`.local` 的 HTTP、IPv6 HTTP、外部 SSO 跨源跳转暂不支持，不要关闭证书校验绕过。

## 1. 电脑侧准备

- 读取版本、源码和 [风险](RISKS.md)。使用官方 Android Platform Tools，已有 SDK 可复用。
- 决定使用 Releases APK 还是自建。校验 APK SHA256 和发布记录中的签名指纹。SHA256 检测下载一致性，不代替来源可信性。
- 先确认用户同意连接哪台电视，再按厂商支持路径开启调试并由用户在电视上授权。不同 Android TV 版本的无线配对流程不同；不能把手机教程直接套到电视上。[官方 ADB 文档](https://developer.android.com/tools/adb)。不默认 5555，不扫描 IP，不打开公网端口。
- 不使用 `adb tcpip` 改调试模式，也不写持久属性“强制开 ADB”。发现连接失败先查同网段/VPN隔离/授权，有限重试；之后停在可恢复的阻塞说明。

## 2. 只读检查（获得读取设备信息授权后）

```sh
adb devices -l
python3 scripts/inspect_tv.py --serial '用户确认的设备序列号或地址'
```

脚本只查询少量设备属性、默认 HOME 和 WebView，不会连接新地址、安装、发按键、读取账号或导出整机快照。需要 `adb` 在 PATH；也可以设置 `TVHOME_ADB` 为官方 adb 的绝对路径。报告本地保存时放 `local/`；分享前脱敏序列号/地址。

确认 `model/brand/build/SDK` 与用户设备一致；默认 HOME 必须有可用的原厂回路。以具体固件为准，不凭“同型号教程”断言兼容。没有 ADB 也可用厂商正规文件安装路径；不要绕过安装限制。

## 3. 安装普通 App（用户已确认目标和安装范围后）

将以下变量替换为刚核对的目标；**示例不能原样复制**。每次写入前重新核对身份和当前状态。第一次安装前记录是否已有同包名、版本、签名和数据需要保留。不是本项目安装的同名包先停止调查。

```sh
TV_SERIAL='用户刚确认的目标'
adb -s "$TV_SERIAL" shell getprop ro.product.model
adb -s "$TV_SERIAL" shell pm path com.pengboqin.tvhome.preview
# 上一步若存在旧包，先核验旧签名/版本和恢复包；不要直接覆盖。
adb -s "$TV_SERIAL" install -r '已核验的候选.apk'
```

`install -r` 保留既有 App 数据，但不是备份，也不是成功保证。签名冲突、厂商拒绝或版本错误时，**不要自动卸载再装**。用电脑 SDK 的 `apksigner verify --print-certs` 和 `aapt2 dump badging` 对照目标 APK；已装 APK 的导出/本机配置备份也要在授权范围内。首次没有配置可回退到“不再启动此 App”；已有配置需保留之前同签名兼容 APK，见 [恢复](RECOVERY.md)。

安装读回：核对 `dumpsys package com.pengboqin.tvhome.preview` 中 versionCode/versionName，不公开原始输出；确认原厂 HOME 未变。此时停止也完全可以，不必接管桌面。

## 4. 打开与无副作用验证（启动/按键授权另核对）

优先让用户从电视 App 列表打开。已允许启动时：

```sh
adb -s "$TV_SERIAL" shell am start -n com.pengboqin.tvhome.preview/com.linghe.tvhome.MainActivity
```

先用“浏览器能力测试”本地页：方向键聚焦、确认、返回、退出。它不连接 HA。实际遥控器由用户验收；ADB 的虚拟按键只能证明一条输入路径。确认系统 Home、输入源和音量仍由系统处理，打开其他 App 后本工具不抢前台。HDMI、CEC、光纤音响的测试可能干扰正在使用的人，应约定时段，不自动加音量或关机。

App 因故被停在后台不是“需要强制置顶”的证据。先记录何时切换、哪个设备/遥控器触发，避免用开机/全局按键服务掩盖原因。

## 5. 配置 HA

在“外观与连接 → 家庭页面地址”填自己的页面，如 `https://home.example.com/dashboard/home`。示例域名不是公共 HA 服务。IME 可能把 URL 改为中文或全角字符；优先手动粘贴并逐字核对，不要反复发送错误文本。App 只在点击“粘贴网址”时读取剪贴板；外部 ACTION_SEND 只预填地址，仍需用户保存。

登录由用户本人完成。首次只观察是否渲染和可退出，**不要点击真实开关测试遥控器**。HA 自定义卡片、旧 WebView、SSO/MFA和跨源外链可能不兼容。当前没有通用鼠标模拟/网页焦点补丁，不承诺每个卡片可用遥控器操作。无法安全浏览时暂停接入，原 HA 配置不变。

VPN 由用户自己的 VPN 软件处理。本 App 不配置路由、DNS、证书或绕过访问控制。

## 6. 交付与接续

向用户报告：安装包来源/版本/哈希/签名、原桌面是否保留、真正验证的遥控器路径、HA 到登录页还是已登录仪表盘、HDMI/音频实际验证情况、剩余问题和退出/恢复命令。不把“已安装”写成“全兼容”。是否保留 ADB 由用户选择；日常使用本 App 不需要 ADB，未知电脑应撤销授权，测试后可在原系统设置关闭调试。

最后保留当前和上一份可用 APK 及本地签名，不清用户数据、不删除私钥。不自动建立定时远程控制或常驻监控。
