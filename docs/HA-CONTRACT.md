# HA通用接入与电视页面契约 · v1草案

2026-10-23。用户已认可原生电视方向，本轮优先统一接口、结构、素材；尚未实现Android原生HA客户端，也没有新APK。每位用户连接自己的局域网HA，数据直接往返电视与其HA，不依赖作者家的实体ID、自定义组件、NAS服务或云中转。

## 接入流程

填写实例地址 → 完成本人HA授权 → 读取配置/可见实体/服务能力 → 自动展示天气、灯光/开关和自动化 → 按可用房间资料分组。一个电视配置一个实例；更换实例时清除前一实例的状态缓存和选择，凭据单独管理。

单独IPv4可规范为http://<IP>:8123；明确端口原样保留，完整HTTPS地址也支持。首版局域网HTTP沿现有RFC1918字面IPv4规则，不扫描其他设备、不猜网段、不改变DNS/VPN/网关。HTTP局域网连接没有传输加密，只适合用户信任的家庭网络；支持有效证书的HTTPS，不提供忽略证书错误的开关。IPv6/mDNS不在首版地址支持承诺内。

IP不是授权。优先正常HA OAuth授权码流程，原生端使用PKCE/state并安全保存刷新会话；HA client_id/原生回调声明、实际实例的PKCE支持需要实现时核对，不能假设完全离线时自定义scheme验证必然成功。自定义回调可能要求HA读取公开client_id元数据，纯离线家庭需要明确备用流程。可保留本地输入用户自己创建的访问令牌作为兼容入口，不从作者HA复制凭据，不伪造内建扫码登录。设备凭据不得进入布局导出、Git、日志或截图。已有WebView登录状态不自动等于原生API会话，不能直接抽取其localStorage令牌。

## 接口边界

参考[官方WebSocket API](https://developers.home-assistant.io/docs/api/websocket/)、[认证](https://developers.home-assistant.io/docs/auth_api/)、[天气](https://www.home-assistant.io/integrations/weather/)、[自动化状态与动作](https://www.home-assistant.io/docs/automation/basics/)。

| 能力 | 读取/订阅 | 用户主动操作 |
| --- | --- | --- |
| 初始实例 | get_config / get_services / get_states | 无 |
| 持续状态 | subscribe_entities，带明确entity_ids；支持版本核对及降级 | 不订阅全事件总线、不用无限轮询 |
| 天气 | weather实体state及temperature/temperature_unit等属性 | 当前天气无需动作；预报按支持能力调用weather.get_forecasts并请求返回数据 |
| 开关 | switch/light实体on/off、不可用与设备能力 | 精确目标的turn_on/turn_off；不写/api/states伪造状态、不用toggle做网络重试 |
| 自动化 | automation实体on/off，last_triggered/current/mode | 只做turn_on/turn_off，停用明确stop_actions=false；不把启用混成trigger执行 |
| 分组 | area/entity/device registry，可用时关联entity区域→device区域 | 无权限/无registry/未分组时仍按域显示；不要求管理员只为读分组 |

get_services存在不代表用户有权控制每个实体；权限拒绝必须按服务端结果显示。自动化on/off是规则是否启用，current是当前运行/排队数量；缺少current不能填0，queued模式不能把队列数当作正在同时运行数。last_triggered也不等于执行成功，不显示虚构的成功次数。

预报不再假定在weather.attributes.forecast。只有当前天气也能完整使用；多天气源可切换，缺温度/风速等属性显示缺省，不猜温度，不把缺失当0，单位沿HA提供值。

自动发现是识别和展示，不是自动执行。仅首版支持的weather/light/switch/automation进入候选；元数据可用时排除禁用、隐藏、诊断和配置实体。实体没有registry记录仍可显示在“未分组”；新实体进入候选，不悄悄改变用户收藏。实体名、房间名、时间单位均来自对应家庭，不依赖中文固定名称。普通switch可能对应高风险设备，自动发现不能保证识别其物理用途；初次接入先预览/选择允许控制的设备，不全量开放未知开关。

## 电视内部接口（计划）

HaTransport负责连接、协议消息、超时、认证失效和重连；HaRepository负责实例隔离、实体快照与订阅增量；CapabilityMapper负责天气/开关/自动化显示模型；ActionController负责明确动作、按实体防重、回读和失败；界面只消费显示模型和动作结果。首批保持现有Java工程，新增基于Android标准HTTP API的原生客户端，加一个经选定的WebSocket实现（现有App尚无HTTP/WS客户端），不为界面重写引入全套新跨平台引擎。设计层合成适配器与未来真实适配器消费同一模型约定。

请求被接收不等于设备状态改变。控制后保留原状态并显示处理中，等待HA权威状态；超时或断线标记“未确认”，不自动重发写请求。重新连接先取完整快照，拒绝跨实例/旧连接代次的迟到结果。只读请求可以有界退避；页面退后台暂停非必要数据工作。

## 页面结构（用户指定双标签）

底部全局四标签：桌面、家庭、应用、设置，在本App常规页面常驻。侧栏是当前标签内部的分类，不复制底栏：家庭内为概览、天气、自动化和房间；应用内为全部、收藏、服务；设置内为外观、HA连接、遥控器、关于。桌面无侧栏。侧栏有展开与图标窄栏状态，折叠不切页/不改变设备状态；支持按钮与本App内MENU收放，不接管系统音量/信号源键。离开本App进入原电视或第三方App后没有我们的悬浮底栏。

内容区最后一行向下进入底栏；底栏向上返回当前页上次的内容焦点；内容左边界进入侧栏；侧栏向右返回当前内容焦点。展开侧栏不生成另一套焦点树。Back依次关闭对话框→收起展开侧栏→页面内返回/当前分类概览→桌面→退出确认，焦点随同恢复。没有侧栏的页面跳过该层。确认键长按不重复发家电动作，正常方向键长按移动保留。

桌面默认露出天气、常用开关与App入口；家庭页自动列出发现的设备/房间，天气单独提供详情，自动化提供规则启停和状态；未连接/无实体有对应空态。底栏保留位置和选中态，离线不让天气和开关看起来仍是实时。

复刻现有HA主页的信息层级与功能，不承诺自动解析Lovelace或自定义卡片。通用API没有每家的户型几何，户型作为后续可选本地素材；房间/天气/开关/自动化这批不以户型导入为前置条件。

## 本轮完成边界

本轮交付接口契约、统一设计素材、合成数据映射与可操作方向稿；真实HA只读核对类别/属性/服务及分组能力，凭据和原始家庭数据不公开。没有真实开关/自动化启停、预报动作、HA配置修改、电视安装或系统变更。生产认证和网络客户端留待下一实现批次，不能把模型验证算作客户端已实现。
